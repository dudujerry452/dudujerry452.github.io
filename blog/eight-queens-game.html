女朋友发我一个微信小游戏(已经进不去了, 所以没图, 悲). 对NxN的棋盘, 规则如下:

  1. 每种颜色有一个国王
  2. 每一行和列有且仅有一个国王
  3. 国王之间八方向上不能相邻

左键标记此处没有国王, 右键标记国王:

可以看出, 规则2和3是八皇后问题的变种, 部分规则替换为国际象棋中"国王"之规则, 且增加了颜色约束.

对纯粹的八国王问题, 如下搜索:

cpp
void count(int** map, int x) {

  if(x == N) {
    g_cnt ++; 
    return; 
  }
  int i;
  for(i = 0; i < N; i ++) {
    if(checkpos(map, x, i)) { // 判断纵横/邻居是否有国王
      map[x][i] = x+1; 
      count(map, x+1); 
      map[x][i] = 0; 
    }
  }
  return; 
}

可知所有合法摆放位置有5242种. 然而, 我们感兴趣的是对染色方案与摆放位置之间的关系!

  1. 给定摆放位置, 是否存在具有唯一解的染色方案?

是的! 任意摆放至少存在2种染色方案: 对每一列用一个颜色; 对每一行用一个颜色. 这是一个P(FP)问题, 可以在时间验证.

  1. 给定摆放位置, 是否能在多项式时间内找出下一个具有唯一解的染色方案?

这是一个枚举问题, 我猜可能是DelayP的, 也有可能是IncP的.

  1. 给定摆放位置, 具有唯一解的染色方案数量有多少?

这是一个#P问题, 并且有可能是#P-Complete的, 属于PSPACE范畴. 毕竟, 仅仅验证答案是否正确就有可能要遍历一个摆放位置所有的合法染色方案; 合法的染色方案按染色区域的面积计数有种可能, 再分别乘每种颜色的形状可能性, 一共接近的数量.

那么, 已经知道了枚举十分困难, 我们如何构造这个游戏呢? 注意到我们不需要严格地构造一个"不重复枚举所有具有唯一解的染色方案"的枚举器, 只要能均匀采样就好.

为了避免空解, 我们先枚举出摆放位置, 再以摆放位置为约束染色. 染色使用四方向概率扩展的元胞自动机即可. 代码如下:

cpp
int** scan(int **pmap, unsigned int seed) {
  int vis = N;
  int** map = newmap(); cpymap(map, pmap); 
  int** nmap = newmap(); cpymap(nmap, map); 
  srand(seed); 
  int i, j; 

  while(vis < N*N) {

    for(i = 0; i < N; i ++)
      for(j = 0; j < N; j ++) {
        if(map[i][j] != 0) continue; 
        
        int dir = rand()%4; 
        int nx = i + dirx4[dir]; 
        int ny = j + diry4[dir];
        if(nx < 0 || nx >= N || ny < 0 || ny >= N) continue; 
        nmap[i][j] = -abs(map[nx][ny]); 
        if(nmap[i][j] != 0) vis ++; 
      }

    int** temp = nmap; 
    nmap = map; 
    map = temp; 
    cpymap(nmap, map); 
  }

  free(nmap); 

  return map; 
}

构造出染色方案后, 检查其是否大于一个解, 若大于则换个种子, 重新染色. 若超过3000次染色都没找到唯一解的染色方案, 就换一个摆放方案. 这样, 我们就实现了对具有唯一解的染色方案的均匀采样, 从而实现了游戏内容!

当然, 这样的实现是不完备的, 可计算性没有证明, 代码的性能也有优化空间. 但俗话说的好能跑起来就别动了, 这套逻辑的采样时间在500ms-1500ms之间已经足够用了, 也就是开头的游戏.
