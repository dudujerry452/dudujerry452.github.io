架构 ​

约束 ​

根据我自己的喜好, 我准备:

  1. -std=c++20
  2. 一份代码独立编译出CPU版和CUDA版
  3. 函数式编程
  4. CMake作为构建系统
  5. 尽可能减少依赖

CPU版和GPU版有相当一部分共用代码, 于是我们将通用代码用宏包装, 写为.h和.cpp, 这部分代码根据编译选项, cmake收集相同的文件后, 用g++或nvcc编译为一个库.

需要注意的是, nvcc本身就会编译两份代码, 其中host那一份本质上也是用g++编译的, 但这不等于只用g++编译! 为了区分, 需要判断"是nvcc且在device下编译"时才能使用CUDA专用特性.

需要注意, nvcc编译出静态库时默认不导出符号链接, 需要设置cpp文件为

cmake
  set_target_properties(the_lib_cuda_version PROPERTIES CUDA_SEPARABLE_COMPILATION ON)

才能在可执行文件调用库中的符号.

剩下不通用的代码, 大部分是并行控制代码, 比如kernel以及openmp包装函数, 这些用模板特化, 根据编译选项收集各自模式下的文件, 编译为可执行文件, 并链接上述库. 比如一个典型的特化:

cpp
#pragma once 

#include "core/basic/types.h"
namespace mps::kernels {
  template<Backend B> struct test_func; 
 
  template<> struct test_func<Backend::CUDA> {
    static void run(i32 n, u32* out); 
  }; 
  template<> struct test_func<Backend::CPU> {
    static void run(i32 n, u32* out); 
  }; 
}

在g++模式下, 由于CUDA对应的cpp文件没有被收集, 于是test_func<CUDA>就没有被特化实现, 若试图调用就会报错, 反之依然.

开始 ​

先用宏包装关键词

cpp
#pragma once


#if defined(__CUDACC__)
  #define MPH __host__
  #define MPD __device__
  #define MPHD __host__ __device__
  #define MPG __global__
#else
  #define MPH
  #define MPD
  #define MPHD
  #define MPG
#endif

#if defined(__CUDACC__)
    #define MPINL __forceinline__
#elif defined(_MSC_VER)
    #define MPINL __forceinline
#elif defined(__GNUC__) || defined(__clang__)
    #define MPINL inline __attribute__((always_inline))
#else
    #define MPINL inline
#endif

这样, 对于公共代码而言, 只要标注MPHD, 在g++模式下该标志会被无视, nvcc模式下则会编译为host和device都支持的形式.

接着写好数学工具库, 有一些更快的函数, 可以用拿进来:

cpp
MPHD MPINL f32 rsqrtf(const f32 x) {
#if defined(__CUDA_ARCH__)
  return rsqrtf(x); 
#else 
  return 1.0f / std::sqrt(x); 
#endif 
}; 
MPHD MPINL f32 sqrtf(const f32 x) {
#if defined(__CUDA_ARCH__)
  return sqrtf(x); 
#else 
  return std::sqrt(x); 
#endif 
}

重复: 需要注意的是, nvcc本身就会编译两份代码, 其中host那一份本质上也是用g++编译的, 但这不等于只用g++编译! 为了区分, 需要判断"是nvcc且在device下编译"时才能使用CUDA专用特性. 用__CUDA_ARCH__判断即可.

几何体 ​

我们用模板特化定义结构体, 并让结构体拥有一个公共的部分

cpp
  template<PrimitiveType T> 
  struct Primitive;

  struct alignas(16) PrimitiveInfo {
    PrimitiveType type; 
    u16 bsdfId;
    u16 texId;
    vec3f wpos;
    vec4f quater; 
    f32 scale; 
  }; 

  // ---------- primitive definations ------------

  template<>
  struct Primitive<PrimitiveType::Sphere> {
    PrimitiveInfo info; 

    f32 radius;
  }; 

  template<> 
  struct Primitive<PrimitiveType::Mesh> {
    PrimitiveInfo info; 

    u32 vertex_cnt; 
    u32 fac_cnt; 

    vec3f *vertices; 
    struct Triangle {
      u32 i[3]; 
    }*faces;

  };

注意保持这些数据为POD, 方便我们拍平转移到GPU上. 我们暂时只定义球体和三角网格.

接着萃取一下类型, 顺便得到16位对齐的内存大小, 方便我们拍平.

cpp
  template<PrimitiveType T>
  struct PrimitiveTrait {
    using Type = Primitive<T>; 
    static constexpr u32 raw_size = sizeof(Type);
    static constexpr u32 aligned_size = (raw_size+15)&(~15);  
  };

通过一些小技巧写出得到类型大小的函数. 然后使用tag-select风格, 这是我们在书写CUDA代码时常用且要熟悉的:

cpp
#define ENUM_PRIMITIVE_FUNC(X) \
  X(Sphere) \
  X(Mesh)
  
MPHD MPINL u32 alignedSizeOfPrimitive(PrimitiveType type) {
    #define DEF_TRAIT(name) \
    case PrimitiveType::name: {return PrimitiveTrait<PrimitiveType::name>::aligned_size; }

    switch(type) {
      ENUM_PRIMITIVE_FUNC(DEF_TRAIT)
      default: { mppanic("Primitive not implemented");  } // panic
    }

    #undef DEF_TRAIT
  }

接着, 我们就可以写出类型无关的代码, 获取每个Primitive对齐后的大小, 然后将不同大小的Primitive写进一块平铺的内存, 后续给GPU.

对于mesh, 我们只记录其基础信息, 顶点, 面等信息放到单独区域寻址.
