引子 ​

Cpp模板常常让我们感到很困惑, 今天我们来弄明白.

Haskell ​

本文默认读者对Haskell和C++的模板系统有基本的了解.

因为学习Haskell后, 回头看C++的模板元编程(TMP), 将拥有一种居高临下的视角, 并意识到它们不过是Haskell的灵魂戴着C++的脚镣在跳舞. 本文旨在帮助那些学习过纯函数式语言的人们快速入门TMP, 也是为了提示直接学习TMP并不是学习TMP的最好途径.

Haskell是非常简洁优美的纯函数式语言. 而恰好, TMP与之类似, 都满足:

  • 无副作用
  • 数据不可变
  • 递归代替循环

Haskell中定义函数的方式:

haskell
-- 类型签名：函数名 :: 参数1类型 -> 参数2类型 -> ... -> 返回值类型
函数名 :: 类型 -> 类型 -> 返回值类型

-- 函数定义：函数名 参数1 参数2 = 函数体表达式
函数名 参数1 参数2 = 函数体

可以这么定义:

haskell
addOne :: Int -> Int
addOne x = x+1

Kurry化:

haskell
addTwo :: Int -> Int -> Int
addFour :: a b= a + b
addFour 5 -- 得到的类型是函数, 类型是Int -> Int

模式匹配:

haskell
len :: [a] -> Int 
len [] = 0
len (x:xs) = 1 + len xs

map:

haskell
map :: (a->b) -> [a] -> [b] 
map _ [] = []
map f [x:xs] = f x : map f xs

monad:

haskell
bind :: M a -> (a->M b) -> M b
bind (M x) f = f x

更多关于Haskell的有趣知识, 请参阅The Book.

模式匹配 ​

模式匹配是函数式/声明式语言的基因, 它取代了条件判断, 并与递归合作的很好. Haskell和TMP均支持模式匹配! 例如:

计算阶乘:

cpp
// cpp
int factorial(int n) {
    if(n == 0) return 1; 
    else return n * factorial(n-1); 
}
haskell
-- haskell
factorial :: Int -> Int 
factorial 0 = 1
factorial n = n * factorial (n-1)

模式匹配取代了if判断终止条件. 接下来讲两种不同的写法.

模板特化 ​

例1: 用TMP中的模板特化模仿haskell的写法, 写出阶乘.

cpp
template<int> 
struct factorial;  // factorial :: Int -> Int

template<>
struct factorial<0> {
    static constexpr int value = 1; // factorial 0 = 1 
};

template<int N> 
struct factorial {
    static constexpr int value = N * factorial<N-1>::value; // factorial n = n * factorial (n-1)
};

我们注意到, 其实Haskell关于模式匹配的定义

haskell
func :: Type1 -> Type2 -> ReturnType

func a b                = BranchBody1  
func (Constructor x) y  = BranchBody2 -- unfold Type1
func _                  = DefaultBody

可以翻译成 TMP的元函数定义:

cpp
template<Type1, Type2>
struct func; 

template<Type1 arg1, Type2 arg2>
struct func<Type1 a, Type2 b> { 
    static constexpr ReturnType value = BranchBody1; 
};
template<InnerType arg1, Type2 arg2>
struct func<Constructor<arg1>, Type2 y> {
    static constexpr ReturnType value = BranchBody2; 
};
template<> 
struct func {
    static constexpr ReturnType value = DefaultBody;
};

这里有一个重要的不同: Haskell的模式匹配以从上而下为优先级, Cpp的模式匹配则以模板参数有多具体为优先级, 而主模板(也就是名字后面不带<>的模板)是最后匹配的.

Constexpr ​

如果你觉得上面的元函数太过繁琐, C++17提供了if constexpr简化TMP:

例1.1:

cpp
template<int N> 
constexpr int factorial() {
    if constexpr (N == 0) return 1; 
    else return N * factorial<N-1>(); 
}

这样, 定义函数几乎像haskell本身一样简洁. 要写出元函数, 只需要把参数写到模板参数中, 用if constexpr来作条件判断, 但: 失去了模板推导中自带的模式匹配, 也就是我们又回到了用if-else做逻辑的时期.

类型模板参数 ​

在模式匹配章节中我们用的模板参数均为非类型模板参数, 形如template<int N, char C>, 用这些参数进行计算. 但若把类型视作值, 我们是否可以对类型本身进行计算? 答案是可以的! 类型的类型叫作typename, 我们写下template<typename T>, 就可以定义出类型模板参数, 参数本身就是类型!

例如, 假若定义 template<typename T> void func(T a);, 那么对任何类型如int就可以通过func<int>((int)a)或func((int)a)(模板推导)调用.

Haskell并不鼓励用户在编译期对类型本身进行计算, 而是在编译期提供了强大的代数数据类型(ADT), 在运行期对类型进行模式匹配而非对类型进行运算或改变类型本身.

相反, C++ TMP本身就是hack出来的, TMP的精神就是用特化和递归, 在编译期吐出一个个全新的类型. 而有了类型模板参数, 我们计算出新类型的难度并不高, 而且也很有意思!

我们从判断类型是否相等开始:

例2:

判断类型是否相等.

c++
template<typename T, typename U> 
struct isSameType {
	static const bool value = false; // Default Branch
}; 

template<typename T> 
struct isSameType<T, T> {
	static const bool value = true; 
};

我们看到, 只要把非类型模板参数(e.g.template<int N>换成类型模板参数template<typename T>), 就可以像对非类型模板参数那样进行模式匹配了! 换句话说, 通过模板特化带来的模式匹配, 我们可以以计算值相同的方式计算类型. 例2中的例子, 其实更像是对值的运算, 若把类型看作类型为Type的值, 那么上述代码在Haskell中类似于:

haskell
isSameType :: Type -> Type -> Bool 
isSameType T T = True 
isSameType _ _ = False

因此, 在类型计算上, TMP甚至比Haskell更具优势, 在这里, 类型也是一等公民!

接下来, 我们看下一个例子:

例3:

剥离容器(指针)外壳.

haskell
unwrap :: M a -> a
unwrap (M x) = x
cpp
template<typename U> 
struct unwrap {
    using type = U; 
}; 

template<typename U>
struct unwrap<T*> {
    using type = T; // (Pointer T) = U
}

其实本例中Haskell并没有对类型做运算(剥离容器类型), 而是从容器中拆出了值. 然而, TMP却可以直接把类型表面的容器剥离掉! 当我们书写unwrap<int*>::type时, 其类型就是int, 我们剥离了类型的外壳.

当然, TMP也可以像Haskell例中在运行时拆出容器中的值, 使用函数重载(或称替代特化)的模式识别特性:

cpp
template<typename T>
struct optional { // notice: not std::optional
    bool has_value = false;
    T value;
};

template<typename T>
T unwrap(T& a) {
    return a;  
}
template<typename T>
T unwrap(optional<T>& a) {
    return a.value; 
}

注意: 函数不能偏特化. 因为偏特化和重载的模式匹配引擎会相互冲突... e.g.

cpp
template<typename T> 
void foo(T*); 
template<typename T> 
void foo(T); 

template<> 
void foo<int>(int*);

出于某种原因, 全特化foo挂载到了主模板void foo(T)上! 那么调用foo((int*)nullptr)的时候, 匹配的主模板void foo(T*)没有特化, 导致直接调用了void foo(T*)! 特化完全被忽略了. 这来自学界一次著名的讨论[1].

[1] Sutter, H. (2001). Why not specialize function templates?. C/C++ Users Journal, 19(7), "Sutter's Mill" Column.

练练手 ​

我们知道将类型在TMP中是一等公民后, 我们可以模仿Haskell的代数类型系统, 用TMP的方式做出一个List!

例4:

实现异构列表, 定义为

haskell
data HCons a b = HCons a b

定义类型 ​

我们模拟Haskell的代数类型系统, 先做出List的类型来. 因为类型a,b没有约束, 所以直接用typename任意匹配:

cpp
struct ListEnd {}; 

template<typename Head, typename Tail>  
struct Cons {}; 

Cons<int, Cons<char, Cons<double, ListEnd>>> list;

通过Cons对两个元素(的类型)的连接, 我们构造出了List的类型部分.

运行期值 ​

现在我们加入运行期值:

cpp
struct ListEnd {}; 

template<typename Head, typename Tail>  
struct Cons {
  Head head; 
  Tail tail; 

  Cons() = default; 
  Cons(Head h, Tail t): head(h), tail(t) {}
}; 

Cons<int, Cons<char, Cons<double, ListEnd>>> list = {
  1, {'a', {3.14, {}}}
};

我们在编译期构造出了异构列表!

辅助函数之一 ​

为了让其更易用, 我们添加辅助函数. 通过可变参数包, 我们得以写出:

cpp
auto make_list() {
  return ListEnd{}; 
}
template<typename First, typename... Last> 
auto make_list(First first, Last... last) {
  return Cons{first, make_list(last...)}; 
}

测试:

cpp
auto list = make_list(1, 'a', 3.14);
auto list2 = 
cout << list.head << " " << list.tail.head << " " << list.tail.tail.head << endl; 
// output: 1 a 3.14

可以看到, 我们几乎做出了一个std::tuple. 通过C++ TMP强大的可变参数和自动推导, 我们能在编译期定义出C++原生并不存在的递归数据类型(及其扁平构造函数)!

辅助函数之二 ​

当然, 我们需要get<n>()和length函数! 这里, 我们用到非类型模板参数, 为Cons和ListEnd添加成员函数get和length:

cpp
struct ListEnd {
  template<int N>
  auto& get(){
    static_assert(false, "Out of Index");
    return *this; // make return value existing
  }
  constexpr int length() const {return 0; }
}; 

template<typename Head, typename Tail>  
struct Cons {
  Head head; 
  Tail tail; 

  Cons() = default; 
  Cons(Head h, Tail t): head(h), tail(t) {}

  template<int N>
  auto& get(){
    if constexpr (N > 0) return tail.template get<N-1>(); 
    else return head;
  }

  constexpr int length() const {
    return tail.length() + 1; 
  }
};

测试:

cpp
auto list = make_list(1, 'a', 3.14);
cout << list.get<1>() << endl; // output: a
cout << list.length() << endl; // output: 3
// cout << list.get<5>() << endl; // error

全局类型约束 ​

Haskell的非异构链表定义为data [] a = [] | a : [a], 其在全局有"所有的a类型相等"之约束. 我们也可以增加这样的约束:

cpp
template<typename T> 
struct List {

  struct ListEnd {
    template<int N>
    auto& get(){
      static_assert(false, "Out of Index");
      return *this; // make return value existing
    }
    constexpr int length() const {return 0; }
  }; 

  template<typename Tail>  
  struct Cons {
    T head; 
    Tail tail; 

    Cons() = default; 
    Cons(T h, Tail t): head(h), tail(t) {}

    template<int N>
    auto& get(){
      if constexpr (N > 0) return tail.template get<N-1>(); 
      else return head;
    }

    constexpr int length() const {
      return tail.length() + 1; 
    }
  }; 

};

template<typename T>
auto make_list() {
  return typename List<T>::ListEnd{}; 
}
template<typename T, typename... Last> 
auto make_list(T first, Last... last) {
  return typename List<T>::template Cons<decltype(make_list<T>(last...))>{first, make_list<T>(last...)}; 
}

typename & template ​

注意, 此时List<T>变成了依赖类型: 依赖T. C++中, 依赖了参数的模板类型的内部之名称是无法确定的, 比如:

cpp
struct BadType1 {
    static int Internal; 
}; 
struct BadType2 {
    static int Internal(); 
}; 
struct TrueType {
    using Internal = int; 
}
template<typename T> 
auto func() {
	return T::Internal * ptr; 
}

因为给func<T>传入BadType1, BadType2的情况都是合法的, 编译器就不知道用到泛型的地方究竟是类型还是别的东西. 所以, 类似的, 我们需要给List<T>::ListEnd{}加上typename修饰, 告诉编译器这里一定是个类型.

同时, 对于模板也是一样的. 再举个例子:

cpp
struct BadType {
    static int Internal; 
}; 

struct TrueType {
    template<int N>
    int Internal(int a) {return a+N;}
}; 
template<typename T>
auto func() {
    return T::Internal<1>(0); 
}

此时, 若传入BadType, 则T::Internal<1>(0)中的<和>就会被解析为大于/小于号. 含义就变成了int_value < 1 > 0, 返回一个bool值; 而传入TrueType显然也有合法解释. 因此, 编译器要求在模板名前加template来消除歧义. 类似的, 对List<T>::Cons<...>{...}, 我们需要修饰为typename List<T>::template Cons<...>{...}.

另一种写法 ​

或者, 我们也可以用模板特化写出带有类型约束的代码:

cpp
template <typename T>
struct ListEnd {};

// 无声明, 不特化的报错
template <typename Elem, typename Tail>
struct Cons;

// 分支1, 结尾的
template <typename T>
struct Cons<T, ListEnd<T>> {
    using value_type = T;
};

// 分支2, 非结尾的
template <typename T, typename Rest>
struct Cons<T, Cons<T, Rest>> {
    using value_type = T;
};
