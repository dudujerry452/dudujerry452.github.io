引子 ​

C语言的指针声明常常困扰我们, 比如

C
int* (*p[10])(char*, int*);

究竟是什么意思? 一般的方法是"右左法", 从变量名开始, 先向右看再向左看, 遇到括号就重置. 这样的确是正确的, but why?

什么是合法 ​

原理:

  1. []和()是右结合的
  2. []和()不能相邻
  3. *是左结合的
  4. 右结合的优先级高于左结合, 括号可以改变优先级
  5. ()向目前探索到的最左侧寻找返回值类型
  6. 类型声明一定以基本类型结尾

其中, ()代表参数列表. 有了以上原则, 可知:

例1: 根据1,2

c
int [5]a; // 不合法
int (char, int)a; // 不合法
int a[5](char, int); // 不合法

例2: 根据3,

c
int a*; // 不合法

例3: 根据4,

c
int *a[5]; //代表数组, 内容是指针 
int *(a[5]); // 与上面等价
int (*a)[5]; // 代表指针, 指向数组

例4: 根据5,

c
int (*a)(char, int); // 返回值类型是int
int *a(char, int); // 根据4, (char, int)先被解析; 
                   // 因此此时最左端为*, 返回值为int*

例5: 根据6,

c
// 全都不合法
a; 
*a[5]; 
a int; 
a[5] int;

游标模型 ​

看到这里, 我们悟到, 在满足6条原理的情况(也就是合法)时: 变量解析时存在左右两个游标, 其方向分别只能向左向右, 且右游标优先级更高, 除非有括号改变优先级. 我们来看回开头例子.

c
int* (*p[10])(char*, int*);
       ^               
// 初始游标均在变量名
int* (*p[10])(char*, int*);
       ^ ^
// R优先, 前进, 得知: p为数组. 
int* (*p[10])(char*, int*);
      ^     ^ 
// R继续前进, 撞到括号, 换L. 得知: p为数组, 其类型为指针.
int* (*p[10])(char*, int*);
     ^      ^ 
// L撞到括号, 重置为R优先
int* (*p[10])(char*, int*);
     ^        ^ 
// R优先, 前进, 得知: p为数组, 其类型为指针, 其类型为指向参数为(char*, int*)的函数
int* (*p[10])(char*, int*);
   ^                      ^
// R继续, 前进, 撞到分号, 换L. 得知: p为数组, 其类型为指针, 其类型为指向参数为(char*, int*)的函数, 其返回值为指针
int* (*p[10])(char*, int*);
^                         ^
// L继续, 前进, 遇到基本类型, 结束. 得知: p为数组, 其类型为指针, 其类型为指向参数为(char*, int*)的函数, 其返回值为指针, 指向int类型.

转换为顺序 ​

我们将例子按解析顺序写出来:

c
int* (*p[10])(char*, int*);
p [10] * (char*, int*) * int

可以发现, 这正是"p为数组, 其类型为指针, 其类型为指向参数为(char*, int*)的函数, 其返回值为指针, 指向int类型"的顺序描述.

这让我们想到了对AST进行先序遍历! 实际上, 正是如此. C使用近似的LR(k)文法解析器得到了AST, 然后使用函数grokdeclarator自底向上遍历语法树(相对于我们的解释顺序, 它的顺序是相反的, 也就是最先解析最外层的基本类型).

例子 ​

现在, 我们彻底搞懂了, 于是可以解释这些古神类型 (别怀疑, 它们是可以通过gcc编译的):

c
int *(*(*(*(*p)(char, int))(char, int))(char, int)); 
int *(*(*(*p[10])(char, int))[10])(char, int);
  1. 一个指向参数为(char,int)且返回值为指向参数为(char,int)且返回值为指向参数为(char,int)的且返回值为int*的函数的指针的函数的指针的函数的指针的函数的指针.
  2. 一个数组, 内容是指向参数为(char,int)且返回值为指向一个数组, 内容是指向参数为(char,int)的且返回值为int*的函数的指针.

不要被其含义迷惑了, 其构造方式就是先写出它们的顺序表达式, 比如2对应的

p [10] * (char, int) * [10] * (char, int) * int

其中, [10] type 代表这是一个数组, 其元素类型为type; * type代表这是一个指针, 指向type. 最终, 一定以一个基本类型收尾(不然总有type需要归约). 写成这种形式后, 再用括号约束表达式, 将这个顺序构造出来, 就可以写出这些古神类型了.

const ​

const的声明很容易理解:

  1. 永远修饰左边的东西;
  2. 如果左边什么都没有(且右边是基本类型), 那么修饰右边;
  3. 受括号影响.
c
int const * p; // 有左侧, 适用1
const int * p; // 等价, 适用2
int (const *) p; // 不合法, 修饰非基本类型时不适用2

将

c
int * const (* const p)(char, int);
const int p; 
int const p;
int const *p;

写为顺序形式:

c
p const * (char, int) const * int 
p int const
p const int 
p * const int

发现在顺序下, 无论如何, const总是修饰其右侧的类型, 除非它是最后一个token.

typedef ​

有时候我们发现类型太复杂了, 想把某个类型换成一个别名. 我们可以使用typedef.

只要将变量声明时的变量名换成类型别名, 就可以定义别名. 比如:

c
// int *(*(*(*(*p)(char, int))(char, int))(char, int)); 
// 替换为
typedef int *(*(*(*(*ComplexType)(char, int))(char, int))(char, int)); 
ComplexType p; // 等价于int *(*(*(*(*p)(char, int))(char, int))(char, int));
