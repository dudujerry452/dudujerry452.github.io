有时候我们的CMake项目依赖两个项目，但这两个项目包含了相同的库，这些库构建相同名称的目标，但库版本以及库源代码有一些微小的改动。为了不破坏依赖项目的独立性以方便后续更新，我们需要一个完全独立的方式来构建这些库，就像单独运行一次CMake构建流程一样。

FetchContent ​

对那些高版本、良好配置的Cmake项目，我们可以直接通过FetchContent获取源代码并获得其构建目标，例如声明对spdlog的依赖，并使其可用（下载）：

cmake
FetchContent_Declare(
    spdlog
    GIT_REPOSITORY https://github.com/gabime/spdlog.git
    GIT_TAG        v1.14.1
)
FetchContent_MakeAvailable(spdlog)

之后，构建目标已经进入Cmake构建流程，直接使用即可：

cmake
target_link_libraries(my_app PRIVATE spdlog::spdlog)

ExternalProject_Add ​

较为重型的方案，同时适合网络拉取和包含本地另外的Cmake项目。

对本地项目，假设我有一个生成可执行文件的项目Markerauto2：

  • 位置在该Cmake文件同目录
  • 构建中间文件存放在[二进制目录]/MARKERAUTO2位置下（避免与主项目同名构建文件重名，例如使用同名库）
  • 构建目标放在[二进制目录]/bin下

可以如下操作：

cmake
# --- 生成模块程序Markerauto2 

ExternalProject_Add(
    Markerauto2 # 为这个外部项目构建过程起一个唯一的名字

    # 指定B的源代码目录
    SOURCE_DIR ${CMAKE_CURRENT_SOURCE_DIR}/Markerauto2

    # 指定B的构建目录，这会是 build/B_build/
    BINARY_DIR ${CMAKE_BINARY_DIR}/MARKERAUTO2

    CMAKE_ARGS 
        -DCMAKE_RUNTIME_OUTPUT_DIRECTORY:PATH=${CMAKE_BINARY_DIR}/bin

    # 关键：告诉 ExternalProject 我们不需要下载、更新或打补丁
    # 因为源代码就在本地
    DOWNLOAD_COMMAND ""
    UPDATE_COMMAND ""
    PATCH_COMMAND ""

    INSTALL_COMMAND "" 
)

类似的，对于远程项目，如下操作：

cmake
ExternalProject_Add(
    spdlog_project # 目标名称
    GIT_REPOSITORY https://github.com/gabime/spdlog.git
    GIT_TAG        v1.14.1
    # 关闭我们不需要的步骤
    UPDATE_COMMAND ""
    PATCH_COMMAND ""
    INSTALL_COMMAND ""
    # 指定子项目的构建目录
    BINARY_DIR ${CMAKE_BINARY_DIR}/spdlog-build
    # 告诉子项目把它生成的库放到哪里
    CMAKE_ARGS -DCMAKE_ARCHIVE_OUTPUT_DIRECTORY=${CMAKE_BINARY_DIR}/lib
)

需要注意的是，ExternalProject_Add不会暴露构建目标，是一次完全独立的构建，只会提供构建的目标文件本身，这也意味着你需要手动根据路径添加目标文件的链接、依赖。
