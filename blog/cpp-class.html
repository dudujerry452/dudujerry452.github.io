引子 ​

cpp的特殊成员函数常常使我们困惑, 今天我们来搞明白.

使用C++14/17, 不会涉及C++20.

例子 ​

在下面的演示中, 我们将部分地使用一个智能指针类作为例子. 现在, 我们来写一些初始代码:

cpp
#ifndef __MY_PTR_H__
#define __MY_PTR_H__ 

#include <iostream> 

template<typename T>
class my_ptr {
  private: 
    T* ptr; 
    int* ref; 
  public: 
    my_ptr(T* origin) {
      ptr = origin; 
      ref = new int; 
      (*ref) = 1; 
    }
    my_ptr(const my_ptr& other) {
      ptr = other.ptr; 
      ref = other.ref; 
      (*ref) ++; 
    }
    ~my_ptr() {
      downcount(); 
    }
    void downcount() {
      if((*ref) == 1) {
        std::cout << "pointer delete completely" << std::endl; 
        delete ptr; 
        delete ref; 
      } else {
        std::cout << "pointer counter decrease" << std::endl; 
        (*ref) --; 
      }
    }
};

#include <string> 

void test() {
  my_ptr<std::string> ptr1(new std::string("Hello, ptr!")); 
  my_ptr<std::string> ptr2(ptr1); 
}

#endif

输出

sh
pointer counter decrease
pointer delete completely

可以看到, 该类能拷贝另一个指向相同资源的智能指针, 并维护引用计数.

特殊函数 ​

五法则 ​

编译器生成6个特殊成员函数:

  1. 默认构造函数 T()
  2. 析构函数 ~T()
  3. 拷贝构造函数 T(const T&)
  4. 拷贝赋值运算符 T& operator=(const T&)
  5. 移动构造函数 T(T&&)
  6. 移动赋值运算符 T& operator(T&&)

有且仅有六个函数, 你没写编译器就会帮你写. 这就是这六个函数.

此外, 还有两种特殊函数, 编译器不会自动生成, 因此他们的地位和普通函数一样, 不会破坏平凡性:

  1. 类型转换运算符 operator U() const
  2. 运算符重载 operator

平凡性 ​

当你没修改任何一个特殊成员函数, 成员没有类内赋值, 且成员均有平凡性时(基本类型具有平凡性), 编译器会给予你一个特殊buff: 平凡性.

具体表现为std::is_trivial_v<T>为true.

这就意味着, 你的类型所有生命周期行为, 包括出生(构造), 死亡(析构), 繁殖(拷贝), 转移(移动), 都不需要控制流来额外处理, 都由编译器接管, 类似一块连续内存或基本类型. 此时, 编译器(以及STL)就有能力对你的类型进行优化! 比如std::copy, memcpy等.

1. 拷贝系函数 ​

6个特殊函数中的后4种叫做拷贝系函数, 他们定义清晰, 比较简单.

拷贝构造函数 ​

只要第一个参数是本类型的引用(且其他参数都有默认值), 那么它就是拷贝构造函数, 规定该类型如何复制为一个新的实例.

cpp
my_ptr(const my_ptr& other); 
my_ptr(my_ptr& other); 
my_ptr(my_ptr& other, int arg1=1, int arg2=2); 
// 这些都是合法的拷贝构造函数

拷贝构造函数很重要, 所有该类的按值传递都由拷贝构造函数完成. 因此, 下列操作都是拷贝构造函数完成的. 下面列举几种常见的按值传递情形:

cpp
void func(my_ptr<int> ap); 
my_ptr<int> ptr(new int); 
my_ptr<int> ptr1(ptr); // use it 
my_ptr<int> ptr2 = ptr; // use it 
my_ptr<int> ptr3(new int); 
ptr3 = ptr; // use it
func(ptr); // use it

拷贝赋值函数 ​

拷贝赋值函数和拷贝构造函数是一对.

拷贝赋值函数将已有的实例转化为另一个实例的副本, 拷贝构造函数则是新建另一个实例的副本.

移动版本 ​

移动构造函数和移动赋值函数基本就是拷贝构造函数和拷贝赋值函数的移动版.

构造函数* ​

构造函数不属于6个特殊函数. 但讲默认构造函数之前, 我们先讲一般的构造函数(也就是用户提供(User-Provided)的那些, 带有{}的那种):

cpp
my_ptr<int> p1 = new int; 
my_ptr<int> p2 = {new int}; 
my_ptr<int> p3({new int}); 
my_ptr<int> p4{new int}; // 本质上是等价的, 其细微区别[1]后面会说

以及, 构造函数和类型转换的关系.

构造函数是一种类型转换 ​

构造函数似乎很简单, 传入一些参数, 得到一个实例:

cpp
my_ptr(T* origin) {
  ptr = origin; 
  ref = new int; 
  (*ref) = 1; 
}
my_ptr<int> p(new int); // 传入int*, 得到my_ptr<int>

但在以上定义令以下写法也是合法的:

cpp
void func(my_ptr<int> ap); 
// in some function 
func(new int);

这是因为所有的构造函数都是转换构造函数. 以func(new int); 为例, 向func传入int*时, 发生如下过程:

  1. int*通过构造函数, 隐式转换为my_ptr<int>
  2. my_ptr<int>作为实参被复制, 进入了函数(所以也发生了拷贝构造)

于是注意到, 构造函数本身其实可以视作参数列表U1 arg1, U2 arg2...转换为类的转换规则, 并可以被隐式使用. 上例展示了单个参数(int*)转换为类(my_ptr), 但我们可以用初始化列表来达成任意多参数到类的映射, 比如这个例子:

cpp
class Foo {
    int a,b,c; 
public: 
    Foo(){}; 
    Foo(int a, int b, int c):a(a), b(b), c(c) {}
}; 
void func(Foo f); 
// in some function
Foo f({1,2,3}); 
Foo f1 = {1,2,3}; 
func({1,2,3});

这里顺便解释下不同的构造函数调用方式有什么细微的区别[1].

对Foo f({1,2,3});, 过程为:

  1. 初始化列表{1,2,3}通过构造函数Foo(int,int,int), 构造出了实例f

对Foo f1 = {1,2,3};, 过程则为:

  1. 初始化列表{1,2,3}通过构造函数Foo(int,int,int), 构造出了右值(临时实例)
  2. 右值绑定到编译器自动生成的拷贝构造函数的const Foo&参数, 构造出了实例f1.

带=的初始化称为拷贝初始化, 注意区分拷贝构造函数, 二者不是一个概念.

实际上, 以f1为例, 拷贝初始化在C++14和C++17有微妙的差别. C++17及之后, 引入了强制拷贝消除(Guaranteed Copy Elision), 步骤1被消除, 等价于Foo f1({1,2,3})的写法了. 比较而言, C++14的(也就是我们展示的步骤)更符合已有规则的逻辑推演, C++17则更扁平简洁.

对C++17, 我们可以把所有的

cpp
Foo f({1,2,3}); 
Foo f = {1,2,3};

都看成

cpp
Foo f(1,2,3);

综上所述, 设{a,b,c}为初始化列表, Foo为接受三个参数的类:

构造函数本质上是{a,b,c}转换为Foo的规则.

只要定义了这样的构造函数, 我们可以在任何显式需要Foo的地方写入{a,b,c}, 并将其作为右值使用. 左值怎么办? 只需要先构造出右值, 然后用拷贝构造函数构造出实例即可, 比如:

cpp
Foo f = {1,2,3}; // 等价于 Foo f = rvalue; 
				 // typeof(rvalue) = Foo
				 // 调用了一次构造函数(从{1,2,3}变为rvalue), 一次拷贝构造函数
				 // 当然, 这只是心智模型. 按C++17的工作过程, 只调用了一次构造函数.

构造函数不是一种类型转换 ​

我们来设想这样一种场景:

cpp
void should_pass_my_ptr_to_this_func(my_ptr<int> ptr); 
// in some function 
int* val = new int(5); 
should_pass_my_ptr_to_this_func(val); 
cout << *val; // segmentation fault (core dumped)

我们来梳理一下过程:

  1. val是new分配的空间之指针
  2. val调用构造函数隐式转换为my_ptr<int>, 其内部引用计数初始化为1
  3. 函数结束, my_ptr离开作用域, 进入析构函数, 引用计数归零, 其内部指针被delete, 即val指向的空间被释放
  4. 试图查看val指向的内容, 段错误

根源在于, 无论构造函数给予我们的类型转换多么方便, 转换前后的类型终究不是一个类型. 当我们试图将原始类型当参数中的类型用, 可能正确也可能不正确, 这取决于设计者的意图. 因此, C++提供了关键字explicit让我们控制这种野蛮的转换.

当我们将构造函数更新为explicit:

cpp
explicit my_ptr(T* origin) {
  ptr = origin; 
  ref = new int; 
  (*ref) = 1; 
}

隐式转换被禁止:

cpp
void should_pass_my_ptr_to_this_func(my_ptr<int> ptr); 
// in some function 
int* val = new int(5); 
should_pass_my_ptr_to_this_func(val);  // error: could not convert ‘val’ from ‘int*’ to ‘my_ptr’

my_ptr<int> ptr1 = val; // error: conversion from ‘int*’ to non-scalar type ‘my_ptr<int>’ requested 这是因为int*试图隐式转换为my_ptr失败了
my_ptr<int> ptr2 = {val}; // error: converting to ‘my_ptr<int>’ from initializer list would use explicit constructor ‘my_ptr<T>::my_ptr(T*) [with T = int]’ 这是因为拷贝初始化禁止使用explicit修饰的构造函数
my_ptr<int> ptr3({val});  // 合法
my_ptr<int> ptr4{val}; // 合法

可以看到大部分试图隐式转换都失败了. 因此, 带有explicit的初始化, 只有:

  1. 直接初始化, 包括new, 临时对象构造(return my_ptr<int>(new int); )
  2. 强制转换, static_cast<my_ptr>(new int)

能使用.

2. 默认构造函数 ​

默认构造函数 ​

当用户

  1. 没声明无参构造函数
  2. 或在类内定义了T() = default;时

将使用编译器提供的构造函数. 这个函数不同于构造函数和用户声明的无参构造函数, 是一种独特的特殊函数, 称为默认构造函数.

区分它和用户定义的T() {}和T(T1 a1, ...) {}. 默认构造函数是六种特殊函数的一种, 同时也是一种无参构造函数(意味着它在默认初始化会被调用, 这一点后面会讲).

只要定义了默认构造函数, 就自动支持两种写法:

cpp
struct T {int x; }; 
// in some function
T a; // 默认初始化, x = <未初始化>
T b{};  // 值初始化, x = 0
T b = T(); // 值初始化
T b = {}; // 值初始化

  1. 默认初始化: 对该实例进行默认初始化;

  2. 值初始化: 它会将实例零初始化后, 对成员中的对象执行无参构造函数. 不要被值初始化的名字迷惑了, 值初始化实际不需要值来初始化. 值得一提的是, 基本类型也有伪默认构造函数, 比如

    cpp
    int a; // 垃圾值
int a{}; // 0
int a[5]{}; // 均为0 
int a[5] = {}; // 均为0

默认初始化 ​

有一定方法触发默认初始化. 当对一个类的默认初始化被触发后, 每个成员有三种可能性, 对应三种处理方式:

  1. 基本类型: 初始化为垃圾值(不初始化)
  2. 对象: 执行其无参构造函数. 若该无参构造函数是默认构造函数, 那么就对该对象递归地进行默认初始化.
  3. 数组: 挨个执行默认初始化, 元素分类同1, 2

触发默认初始化的方式有很多种:

  1. T a; 且T() = default;, 关于default我们将在 默认初始化的部分讲解.
  2. new T; 且T() = default;. new的很多行为和直接定义类似.
  3. T() {}, 所有没在:后的初始化列表的成员都会默认初始化
  4. Derived() {}派生类构造时没在:后构造基类, 这时基类触发默认初始化

可以注意到, 几乎所有的没有初始化的东西都落到默认初始化里了, 会带来很多垃圾值. 因此, 默认构造函数的优点在于它提供了值初始化, 值初始化有零初始化, 能将所有垃圾值一扫而空.

我们来举个例子:

cpp
struct U1{
    int x, y; 
    U1():y(0) {} // 取消默认构造函数
}; 
struct U2{
    int x; // 有默认构造函数
}; 
struct T{
    U1 u1;
    U2 u2;  
}; 
// in some function 
T a; // a.u1.x为垃圾值, a.u1.y=0, a.u2.x为垃圾值
T a{}; // a.u1.x=0, a.u1.y=0, a.u2.x=0

3. 析构函数 ​

子类的析构函数调用前, 会先调用父类的析构函数. 这一点与构造函数一致.

修饰析构函数 ​

析构函数的定义最为精确: 必须是~[类型名](). 然而, 它拥有很多修饰可能性!

  1. virtual ~T(); virtual关键字是最常被用来修饰析构函数的. 这样, 当一个基类指针指向的是子类时, 销毁时能通过虚函数表自动找到子类的析构函数.
  2. protected: ~T(); 类似virtual的功能. 当一个基类指针指向的是子类时, 且析构没声明为virtual时, 销毁将会调用基类指针的析构函数. 然而, 该析构函数是protected的, 外部无法调用, 只能通过子类的析构函数间接调用. 这样, 不需要虚函数表, 且能在编译期禁止错误析构.
  3. private: ~T(); 禁止外部调用delete, 只能通过内部delete this;析构. 可用于单例等.
  4. ~T() = delete; 禁用了析构函数. 此时在栈上创建对象时会直接报错, 因为离开作用域时找不到析构函数. 堆上的对象也会无法delete.
  5. ~T() noexcept(false); 析构函数默认禁止抛异常, 要想抛异常必须这么定义.

伪构造函数 ​

有时候我们需要释放泛型T,, 但它可能是基本类型:

cpp
template<typename T>
void destroy(T* ptr) {
    ptr->~T();
}
// in some function 
int a = 10;
destroy(&a); // 合法

虽然基本类型没有析构函数, 但是这么写更方便. 这就是伪构造函数.

其他特殊函数* ​

运算符重载 ​

运算符重载有两种形式:

  1. a.operator@(b), 改变左操作数, 或者和左操作数强相关的, 比如=, +=, [], (), ->
  2. operator@(a,b), 对称的, 比如+, -, *, ==, <<, >>

它们没什么特别的要求. 硬性规定有这些:

  1. 参数中必须包括一个自定义类型
  2. n元运算符必须有n个参数, 除了()
  3. =, [], (), ->, 只能用第一种形式
  4. ->的返回值必须是指针或者另一个实现了->的对象, 其他返回值均无限制
  5. new必须是void* operator new(size_t, ...), delete必须是void delete(void*, size_t(可选))

具体的规则见cppreference.

类型转换运算符 ​

类型转换运算符只能是第一种形式, 参数个数强制为0, 且无返回值(返回值就是对象的类型). 我们注意到, 类型转换运算符正是转换构造函数的逆操作. 转换构造函数将其他类型转换为对象, 类型转换运算符将对象转换为其他类型:

cpp
my_ptr(T* origin) {
    ptr = origin; 
    ref = new int; 
    (*ref) = 1; 
}
operator bool() {
    return (ptr == 0) ? false : true; 
} 
// in some function 
my_ptr<int> p = new int; // int* => my_ptr
if(p) cout << "Pointer create successfully" << endl; // my_ptr => bool

但这样也会出现问题, 比如

cpp
my_ptr<int> p = new int;
auto x = p + 1;

此时发现auto被推导为int, 因为我们没有实现operator+(my_ptr, int), 导致编译器寻找到将my_ptr => bool => int => operator(int, int)的计算路径, 导致了极为荒谬的结果. 我们为类型转换运算符加上explicit:

cpp
explicit operator bool(){ ... } 
auto x = p + 1; // error: no match for ‘operator+’ (operand types are ‘my_ptr<int>’ and ‘int’)
if(p) { ... } // 合法. explicit operator bool有后门: 能在if, while等条件语句中隐式转换.
